# RoboDock

**robocopy 的图形界面。不用记参数，删文件前一定先告诉你。**

## 为什么做这个

robocopy 是 Windows 自带最快的复制工具之一——尤其是**大量小文件**的场景，
比资源管理器快得多，还自带多线程、断点续传、可靠日志。

但它有三个劝退点：

| 问题 | 具体表现 |
|---|---|
| **参数太多** | 80 多个开关，`/XO`、`/XN`、`/XC` 分不清谁是干什么的 |
| **退出码反直觉** | 返回 `1` 代表**成功**（复制了文件）；只有 `<8` 才算成功 |
| **`/MIR` 会删数据** | 镜像模式会删除目标端的多余文件，而且没有任何提示 |

现有的 GUI 工具大多停在"把表单拼成命令行"，这三个问题一个都没解决。

RoboDock 的取舍是：**先解决这三个问题，再谈功能。**

## 三个设计原则

1. **新手不查文档也能用** —— 简单模式只问 3 个问题
2. **危险操作必须预览** —— `/MIR` 执行前一定看到"将删除 N 个文件"
3. **结果说人话** —— 给你"成功 / 跳过 / 失败 / 删除"四个数字，退出码收进详情

## 快速开始

1. 下载 Release 里的 `RoboDock.zip`，解压到任意目录（免安装）
2. 双击 `RoboDock.exe`
3. 选源目录 → 选目标目录 → 点一种策略 → **先看看会发生什么** → 确认后点 **开始复制**

## 四种复制策略

界面上的四个按钮，对应下面四种行为。**只有第二个会删文件。**

| 界面上的名字 | 实际参数 | 会删目标文件吗 | 什么时候用 |
|---|---|---|---|
| 📄 备份过去 | `/E` | ❌ 不会 | 只增不改，把文件搬过去 |
| 🔁 保持一模一样 | `/MIR` | ✅ **会删除** | 目标要和源完全一致（镜像） |
| ⬆️ 只更新改动过的 | `/E /XO` | ❌ 不会 | 覆盖旧的，但保留目标端多余文件 |
| ➕ 只补缺失的 | `/E /XC /XN /XO` | ❌ 不会 | 目标已有的文件一律跳过 |

## 为什么比资源管理器复制快

- **多线程**（`/MT:32`）：小文件并行复制，避免逐文件往返
- **增量判断**：只比对时间戳和大小，不重复拷贝
- **断点续传**（`/Z`）：大文件中途断了可以接着来
- **大文件模式**（`/J`）：无缓冲 I/O，适合单文件几十 GB
- **无 UI 开销**：不画进度动画、不逐文件刷新窗口

## 常见场景

### 备份照片 / 视频到 U 盘
策略选「备份过去」，路径填好即可。第一次跑完，以后只拷新增的。

### 把项目同步到 NAS
选「保持一模一样」，但注意：**NAS 上多余的旧文件会被删除**。界面上会先列出将删除的数量。

### 迁移大文件到移动硬盘
高级模式里勾上「可断点续传」和「大文件模式」，多线程设为 8 左右。

### 大量小文件快速搬运
高级模式把 `/MT` 设到 32，关闭重试（`/R:0`）可让失败文件快速跳过而不是卡住。

## ⚠️ 危险操作说明

`/MIR` 和 `/PURGE` 会**删除目标端文件**，robocopy 没有回收站。

RoboDock 的四道防护：

1. 策略卡片上的红色警示，执行按钮文字变为「确认镜像并删除」
2. **强制先试运行**，结论卡里"删除 N 个"单独一行红色显示
3. 执行前二次确认对话框
4. 自动开启日志，删除清单单独落盘

## 退出码对照表

robocopy 的退出码是**位掩码**，`<8` 都是成功。RoboDock 会翻译成人话。

| 码 | 含义 |
|---|---|
| 0 | 没有需要复制的文件，也没有失败 |
| 1 | **成功复制了文件**（最常见，是好事） |
| 2 | 目标端检测到额外文件/目录 |
| 3 | 复制了文件 + 目标端有额外项 |
| 4 | 检测到不匹配的文件或目录 |
| 5 | 复制了文件 + 有不匹配项 |
| 6 | 有额外项 + 有不匹配项 |
| 7 | 1+2+4 的组合 |
| **8** | **有文件复制失败**（至少一个） |
| 9–15 | 8 + 对应位（复制失败且伴随上述情况） |
| **16** | **严重错误，一个文件都没复制** |

## 从源码构建

需要 [.NET 10 SDK](https://dotnet.microsoft.com/download)。

```powershell
git clone https://github.com/GCSFML/RoboDock.git
cd RoboDock
dotnet build
dotnet run --project src/RoboDock.App

# 运行测试（测试项目零 NuGet 依赖，离线也能跑）
dotnet run --project tests/RoboDock.Core.Tests
```

发布为可分发版本：

```powershell
# 需要 .NET 运行时的较小版本
dotnet publish src/RoboDock.App -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true

# 免运行时的自包含版本（约 70 MB）
dotnet publish src/RoboDock.App -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:PublishTrimmed=false
```

### 一个实现上的坑（顺便说明为什么这么写）

robocopy 的界面语言**跟随控制台代码页**：同一个程序，英文控制台下输出
`Files :`，中文控制台下输出 `文件:`。所以解析器不能按标签匹配，
而是只依赖结构——摘要表固定是"目录/文件/字节/时间"四行、每行六列；
试运行输出里，要删除的项类别列一定以 `*` 开头，目录路径一定以 `\` 结尾。

反过来利用这个特性：RoboDock 用 `cmd /c "chcp N & robocopy ..."` 指定代码页，
让 robocopy **自己的输出也跟着界面语言走**（中文界面出中文日志，英文界面出英文日志）。

## 环境要求

- Windows 10 / 11（robocopy 是系统自带程序，路径 `C:\Windows\System32\Robocopy.exe`）
- .NET 10 Desktop Runtime（用自包含版本则无需安装）

## 常见问题

**复制到一半能停吗？**
能。取消后已完成的文件保留，下次再跑会跳过；勾了「断点续传」的大文件也能续。

**会覆盖同名文件吗？**
看你选的策略。「备份过去」只覆盖较旧的；「只补缺失的」则不覆盖。

**删掉的文件能找回吗？**
不能。robocopy 不走回收站。这也是为什么 `/MIR` 必须试运行。

**需要管理员权限吗？**
一般不需要。只有勾选「备份模式」（`/B`，可读取无权限文件）时才需要。

**会联网吗？**
不会。无遥测、不上传任何数据，纯本地工具。
